# Railway Deployment Guide

This document outlines deployment configuration for the ASP.NET Core MVC application on Railway.

## 1. Image Storage Providers

The runtime image-storage provider is controlled by `ImageStorage__Provider`.

Supported values:

```text
LocalVolume
Cloudinary
CloudflareR2
```

Phase 1 implements `CloudflareR2` as the provider foundation for new uploads. No production cutover, legacy asset migration, or database URL rewrite is performed by this phase.

## 2. Cloudflare R2 Configuration

Store real values in Railway Variables. Do not commit them to source.

Required keys:

```text
ImageStorage__Provider=CloudflareR2
ImageStorage__AccountId=<secret/config>
ImageStorage__BucketName=<bucket-name>
ImageStorage__AccessKeyId=<secret>
ImageStorage__SecretAccessKey=<secret>
ImageStorage__ServiceUrl=https://<account-id>.r2.cloudflarestorage.com
ImageStorage__PublicBaseUrl=https://<public-media-domain>
ImageStorage__Region=auto
ImageStorage__DefaultPrefix=general
ImageStorage__MenuPagesPrefix=menu-pages
ImageStorage__BranchesPrefix=branches
ImageStorage__NewsPrefix=news
ImageStorage__BrandsPrefix=brands
ImageStorage__MaxFileSizeBytes=52428800
ImageStorage__UsePathStyle=false
ImageStorage__AllowedExtensions__0=.jpg
ImageStorage__AllowedExtensions__1=.jpeg
ImageStorage__AllowedExtensions__2=.png
ImageStorage__AllowedExtensions__3=.webp
ImageStorage__AllowedContentTypes__0=image/jpeg
ImageStorage__AllowedContentTypes__1=image/png
ImageStorage__AllowedContentTypes__2=image/webp
```

`MaxFileSizeBytes` is the canonical storage limit and is 50 MB. Kestrel and multipart form limits remain 60 MB to allow multipart overhead. Do not use `MaxUploadBytes`.

## 3. Prefix Mapping

Cloudflare R2 object keys are generated by category:

* Branch thumbnails -> `BranchesPrefix`
* News/post thumbnails -> `NewsPrefix`
* Menu page images -> `MenuPagesPrefix/<MenuGroup.Slug>`
* Menu group covers -> `BrandsPrefix`

Examples:

```text
menu-pages/truyen-thuyet-champong/1-<guid>.webp
menu-pages/gogi-maru/1-<guid>.webp
menu-pages/kbb-cook/1-<guid>.webp
```

The menu group folder is an R2 object-key prefix displayed as a folder in the dashboard. It is not a physical directory and is not configured through Railway variables. Existing root-level `menu-pages/<filename>` objects are not migrated by Phase 1.1 and remain supported for rendering and deletion.

Object keys are immutable and include GUID entropy. New R2 uploads return public absolute URLs built from `PublicBaseUrl`.

## 4. LocalVolume Legacy Compatibility

`LocalVolume` remains supported for local development and legacy `/uploads/...` URLs. If `ImageStorage__Provider=LocalVolume`, Railway must mount a Volume covering the configured root path.

Typical LocalVolume configuration:

```text
ImageStorage__Provider=LocalVolume
ImageStorage__RootPath=/data/uploads
ImageStorage__PublicBasePath=/uploads
ImageStorage__MaxFileSizeBytes=52428800
```

When `Provider=CloudflareR2`, new uploads do not require a Railway Volume. The application still maps `/uploads` for legacy assets if the configured local upload directory exists; otherwise the route remains present but serves no files.

If `Provider=LocalVolume`, scoped menu-page uploads use the equivalent relative path:

```text
/uploads/menu-pages/<menu-group-slug>/<safe-unique-filename>
```

Physical files are written under `RootPath/menu-pages/<menu-group-slug>/`.

## 5. Other Required Secrets

Configure these through Railway Variables:

```text
ConnectionStrings__DefaultConnection
ResendSettings__ApiKey
AdminBootstrap__Username
AdminBootstrap__Password
AdminBootstrap__Email
AdminBootstrap__RemediateLegacySeed
CloudinarySettings__CloudName
CloudinarySettings__ApiKey
CloudinarySettings__ApiSecret
```

Cloudinary settings are needed only when uploading through Cloudinary or deleting recognized legacy Cloudinary assets.

## 6. Verification

Before production cutover:

1. Run ordinary unit tests.
2. Run the opt-in local R2 smoke test with `RUN_LIVE_R2_TESTS=true`.
3. Confirm upload, object existence, public URL access, delete, and post-delete verification.
4. Confirm no smoke object remains.
5. Deploy only after Railway Variables are populated and startup validation passes.

## 7. Remaining Hardening

Phase 1 does not implement:

* managed asset registry
* shared-reference delete protection
* legacy asset migration
* centralized URL resolver
* decoder or magic-byte image validation
* full create/edit/delete lifecycle ownership refactor

Those items should be addressed before broad production migration of existing assets.
